1) DESCRICAO DOS MODELOS
========================

1.1) Decision Tree
- Modelo supervisionado baseado numa unica arvore de decisao.
- Usa cortes sucessivos nas variaveis para separar classes.
- Vantagens: interpretabilidade alta (regras legiveis), treino rapido.
- Risco principal: se os primeiros cortes forem pouco favoraveis a classe minoritaria,
  o modelo tende a manter baixo recall para doentes.

1.2) Random Forest
- Conjunto (ensemble) de multiplas arvores de decisao.
- Cada arvore treina com variacao nos dados e subconjunto de atributos.
- Vantagens: maior robustez, menor variancia, melhor generalizacao.
- Nesta implementacao: class_weight='balanced_subsample', adequado a desbalanceamento,
  pois reequilibra classes dentro das amostras bootstrap de cada arvore.

1.3) K-NN
- Classificador por vizinhos mais proximos (distancia entre amostras).
- Nao aprende fronteira explicita; decide pela vizinhanca local.
- Sensivel a desbalanceamento e ao valor de K.
- Beneficia fortemente de treino mais equilibrado.

1.4) Naive Bayes (GaussianNB)
- Modelo probabilistico com hipotese de independencia condicional entre atributos.
- Muito rapido e estavel, com boa performance base em muitos cenarios.
- Pode perder desempenho quando as relacoes entre variaveis sao complexas,
  mas costuma manter bom recall quando configurado com dataset mais equilibrado.

3) COMPARACAO TRANSVERSAL
=========================

3.1) Quem melhor deteta doentes (Recall)
- Random Forest (balanced_subsample): 0.8946
- Decision Tree 1:5 balanced + threshold: 0.8836
- Naive Bayes reduzido: 0.6297
- K-NN melhor variante (1:2): 0.5540

3.2) Trade-off principal observado
- Quanto maior o recall para classe positiva, menor tende a ser precision e accuracy global.
- Isto e esperado em problemas medicos de risco quando se privilegia reduzir falsos negativos.

3.3) Robustez por familia de modelo
- Random Forest mostrou o melhor equilibrio para objetivo clinico de triagem (maior recall e F2).
- Decision Tree melhorada chegou perto, mas com menor estabilidade teorica que Random Forest.
- Naive Bayes teve desempenho consistente e simples de manter.
- K-NN variou bastante com o dataset e K, mostrando maior sensibilidade.


4) ANALISE DE APTIDAO PARA CONTEXTO MEDICO
==========================================

Nota importante:
- Este projeto nao substitui diagnostico medico nem validacao clinica formal.
- Os resultados sao de suporte analitico e devem ser interpretados com cautela.

4.1) Criterio medico relevante
- Para triagem de doenca cardiaca, recall alto e geralmente prioritario,
  pois perder um doente (falso negativo) pode ser mais grave do que sinalizar
  um nao doente (falso positivo).

4.2) Aptidao dos modelos
- Decision Tree 85% e Decision Tree 1:5 (sem ajuste de threshold):
  aptidao limitada para triagem medica devido a recall insuficiente.

- Decision Tree 1:5 balanced + threshold:
  apto para triagem inicial (recall alto), mas com muitos falsos positivos.
  Recomendado como camada de rastreio, nao como decisor final isolado.

- Random Forest balanced_subsample:
  melhor opcao entre os modelos testados para triagem medica,
  por atingir o maior recall observado e bom F2.

- Naive Bayes (reduzido):
  opcao simples e eficiente para baseline operacional, com recall moderado-alto.

- K-NN:
  apto como comparador e apoio exploratorio, mas menos robusto para este problema
  quando comparado com Random Forest e Decision Tree balanceada.


5) CONCLUSAO FINAL
==================

Com base nos outputs analisados, o modelo mais indicado para o objetivo de detectar
casos de Heart_Disease em cenario desbalanceado e:

1) Random Forest com class_weight='balanced_subsample' e threshold otimizado.

Justificacao:
- Maior recall (0.8946)
- Melhor F2 entre os cenarios reportados
- Maior robustez por ser ensemble de multiplas arvores

Opcao secundaria forte:
2) Decision Tree 1:5 balanceada com threshold otimizado (recall 0.8836),
   com vantagem de interpretabilidade e desvantagem de menor robustez.

Recomendacao pratica de uso:
- Usar o modelo para triagem/rastreio (priorizando recall), seguido de
  etapa clinica confirmatoria para reduzir impacto de falsos positivos.


6) LIMITACOES E PROXIMOS PASSOS (RELEVANTE PARA ANALISE INTENSIVA)
===================================================================

Limitacoes:
- Validacao baseada em um split de teste fixo (15%).
- Nao ha calibracao probabilistica clinica formal.
- Nao ha avaliacao de subgrupos (idade, sexo, comorbidades) nesta comparacao consolidada.

Proximos passos recomendados:
- Repetir com validacao cruzada estratificada no pipeline final de cada modelo.
- Medir sensibilidade/especificidade por subgrupos clinicos.
- Ajustar threshold com base num custo clinico explicito (FN >> FP).
- Adicionar calibracao de probabilidades (Platt/Isotonic) para suporte a decisao.
